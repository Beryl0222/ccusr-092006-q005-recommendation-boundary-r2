# 推荐兴趣边界自主管理

本项目整理“推荐兴趣边界服务”的领域约定：事件名称、交换字段、脱敏样例与可机检的不变量，
方便业务、客服、运营和研发在同一套术语下讨论。资料只包含领域契约，不包含真实个人信息、
生产连接、外部账号，也不负责训练推荐模型。

## 要解决的问题

- 账号只能看到越刷越窄的首页，看不懂自己被推断出了哪些兴趣、依据是什么、何时过期；
- “不感兴趣”不清楚作用于单条作品、主题还是整个账号；
- 偶然划过的敏感主题被写入长期画像；重置 / 屏蔽后，旧策略换个别名又恢复；
- 分不清“兴趣拓展”与商业投放；撤回请求是否已在所有活跃设备和缓存中生效无法验证。

## 五类领域事件

| 事件 | 含义 |
| --- | --- |
| `SIGNAL_OBSERVED` | 原始信号，来源必须是 `WATCH` / `FAVORITE` / `SEARCH` / `NEGATIVE_FEEDBACK` / `CAMPAIGN` 之一，各自有独立必填字段和有效期。负反馈必须显式声明作用粒度 `ITEM` / `TOPIC` / `CREATOR`。 |
| `INTEREST_INFERRED` | 人类化兴趣条目：可读名称、主题、别名、来源信号清单、敏感度（`STANDARD` / `SENSITIVE`）、留存级别（`SESSION` / `LONG_TERM`）、商业性与有效期、策略版本。 |
| `BOUNDARY_CHANGED` | 用户边界操作：`RESET` / `SUPPRESS` / `LIFT_SUPPRESSION` / `LIMIT_INFERENCE` / `SET_EXPLORATION_FREQUENCY` / `SET_SAFETY_BOUNDARY`。 |
| `PROFILE_ACCESSED` | 推荐引擎每次取用画像的登记：消费者、策略版本、用途、渠道（自然 `ORGANIC` / 广告 `ADS`）、决策 ID、实际使用的信号与兴趣；探索用途必须附频率与内容安全版本。 |
| `WITHDRAWAL_PROPAGATED` | 撤回传播回执：撤回范围与目标、各活跃设备 ACK、各缓存 `EVICTED`（主动失效）或 `EXPIRED`（到期）状态。 |

## 契约强制的关键不变量

1. **敏感主题防误写**：敏感主题仅凭偶然停留（短停留 / 误触）只能写会话画像；进入长期画像必须有搜索、收藏或完整观看等明确行为佐证。
2. **别名不得复活**：主题被屏蔽后，同主题或登记别名的新推断一律拒绝（`suppressed_alias_revival`）；解除屏蔽后，只能依据屏蔽期之后的新信号重建。
3. **重置切断旧依据**：账号 / 品类 / 主题重置后，重置前的旧信号不得支撑新推断（`pre_reset_signal:*`），重置后产生的新信号除外。
4. **来源分类限制**：用户限制某类信号（如运营活动）参与推断后，该来源信号不能再进入兴趣条目。
5. **广告与自然分流**：商业性信号 / 兴趣只能走 `ADS` 渠道；兴趣条目的商业性必须与其来源一致，禁止把运营活动包装成自然兴趣。
6. **探索受控**：多样性探索只能在自然渠道，且实际频率上限与内容安全边界版本必须与用户配置一致。
7. **取用即登记且只取有效信号**：决策只能引用当时未过期、未撤回、未被重置 / 屏蔽的信号与兴趣。
8. **撤回可验证**：`evaluate_withdrawal` 以服务端活跃设备清单为准，所有设备 ACK 且所有缓存主动失效或到期后才判定 `PROPAGATED`；此后新决策再引用该信号会被拒绝（`WITHDRAWN`）。

## 稳定接口（供上游服务与客服工具调用）

- `validate_event(record, history=())`：校验单条事件及跨事件不变量，返回问题代码列表。
- `readable_profile(history, at=None)`：账号自查视图——当前仍有效的人类化兴趣条目、来源信号、有效期，按自然 / 投放分流。
- `explain_decision(history, decision_id, at=None)`：客服解释一次推荐用了哪些信号，给出每个信号在**决策时刻**和**查询时刻**的有效状态（撤回后可直观看到“当时有效、现已撤回”）。
- `evaluate_withdrawal(record, active_device_ids, at)`：验证撤回是否已覆盖全部活跃设备与缓存。

## 目录

- `src/recommendation_boundary.py`：事件词表、字段校验与上述接口。
- `data/sample.json`：单条虚构事件的最小格式样例。
- `data/sample_timeline.json`：覆盖五类事件的虚构时间线（含负反馈、屏蔽、探索配置、投放分流、撤回）。
- `tests/`：保证样例与领域约定一致，并固定全部不变量。
